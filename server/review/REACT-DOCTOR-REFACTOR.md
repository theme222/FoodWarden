# ตรวจและปรับ React Doctor — 2026-11-15

ตรวจด้วย React Doctor 0.9.23 แบบ `--scope full --no-cache` บนสแต็กและขอบเขตเดิม ไม่มีการเพิ่ม dependency เปลี่ยนกฎ หรือเพิ่มรายการยกเว้นเพื่อให้คะแนนสูงขึ้น

| ผลตรวจ                 | ก่อนปรับ | หลังปรับ |
| ---------------------- | -----: | -----: |
| คะแนน                  | 75/100 | 78/100 |
| Errors                 |      0 |      0 |
| Warnings               |     21 |      8 |
| โครงสร้างและความซับซ้อน   |      9 |      0 |
| ประสิทธิภาพ              |     11 |      7 |
| Bugs ตามหมวดของเครื่องมือ |      1 |      1 |

จำนวน warnings เป็นจำนวน diagnostics ไม่ใช่จำนวนบั๊กที่ยืนยันแล้ว คะแนนคำนวณโดยเครื่องมือ จึงรายงานตามผลจริง ไม่ถือว่าครบ 100/100

## ส่วนที่ปรับแล้ว

- [Inventory.tsx](../src/Inventory.tsx): แยก hook จัดการสถานะออกจากสรุปอาหาร ตัวกรอง แถวอาหาร การเลือกหลายรายการ และฟอร์มแก้ไข ใช้ Set สำหรับหมวดโปรดและชื่ออาหารที่ normalize แล้ว แทนการค้นหาของโปรดซ้ำสำหรับอาหารทุกชิ้น
- [Charts.tsx](../src/Charts.tsx): แยก hook โหลดประวัติ ตัวควบคุม กราฟ เหตุการณ์ประตู และค่าที่เลือก คำนวณชุด series ที่เปิดใช้ก่อนวนตัวอย่าง Memoize geometry และเส้นกราฟเพื่อให้การเลื่อนตำแหน่งอ่านค่าไม่สร้างเส้นทุกเส้นใหม่เมื่อข้อมูลเดิมยังใช้ได้
- [LineConnection.tsx](../src/LineConnection.tsx): แยก hook จับคู่ LINE, หัวข้อและสถานะ, การเพิ่มเพื่อน, รหัสและเวลาหมดอายุ และปุ่มของบัญชีที่เชื่อมแล้ว
- [MyAccount.tsx](../src/MyAccount.tsx): แยกการตั้งค่าแจ้งเตือน หมวดโปรด และแถวของโปรด ย้ายข้อความสองภาษาเป็นตารางข้อความ และใช้ Set สำหรับหมวดที่เลือก
- [Settings.tsx](../src/Settings.tsx): แยกคำแนะนำครอบครัว การตั้งค่าทั่วไป โทเคน Gateway สมาชิก และส่วนลบตู้
- [main.tsx](../src/main.tsx): แยก header ออกจากการจัดการสถานะลงชื่อเข้าใช้
- [FavoriteToggle.tsx](../src/FavoriteToggle.tsx): ใช้ตัวเปรียบเทียบชื่ออาหารร่วมกัน โดยเปรียบเทียบแต่ละช่องหลัง normalize แทนการต่อข้อความด้วย delimiter

ไม่มีการแก้ schema, API, การตรวจสิทธิ์, การส่ง LINE, ลำดับ webhook หรือโค้ดของอุปกรณ์

| [personal-notifications.ts](../workers/lib/personal-notifications.ts), `async-await-in-loop` 2 จุด | เป็นการ claim และส่ง outbox ทีละงาน กับการเขียน outbox/cooldown/event receipt ต่อผู้รับ ไม่มีหลักฐานว่าเป็นบั๊ก งานผู้รับอิสระบางส่วนอาจใช้ bounded concurrency ได้หลังวัดภาระ D1/LINE และทดสอบ lease/retry เพิ่ม |
| [telemetry.ts](../workers/lib/telemetry.ts), `async-await-in-loop`                                | แบ่ง D1 batch ครั้งละ 500 คำสั่งเพื่อจำกัดงานแต่ละครั้ง การคง batch แบบจำกัดเป็นพฤติกรรมที่ตั้งใจ ไม่ใช่การยิงคำสั่งฐานข้อมูลทีละ sample                                                                         |
