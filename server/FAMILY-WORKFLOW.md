# ใช้งาน FoodWarden ร่วมกับครอบครัว

ฟีเจอร์นี้เชื่อมหน้า React กับข้อมูลจริงใน Cloudflare D1 และ Durable Objects ส่วนรูปอาหารเก็บใน R2 แบบส่วนตัว ไม่ใช้ข้อมูลตัวอย่างจากไฟล์ต้นแบบ HTML แทนสถานะอุปกรณ์จริง

## เริ่มใช้งานในบ้าน

1. เจ้าของเข้าด้วย Google แล้วสร้างตู้เย็น หน้า Settings แสดงโทเคนสำหรับ Gateway ของตู้นั้น
2. เพิ่มอีเมล Google ของสมาชิกใน Settings โดยให้สิทธิ์ `member` ตามปกติ ใช้ `owner` เฉพาะผู้ที่ควรจัดการสมาชิก โทเคน และการตั้งค่าตู้ได้
3. กดคัดลอกลิงก์ให้ครอบครัว แล้วส่งลิงก์ให้สมาชิกเอง ระบบให้สิทธิ์ตามอีเมล แต่ไม่ได้ส่งอีเมลเชิญอัตโนมัติ สมาชิกต้องลงชื่อเข้าด้วยอีเมลเดียวกับที่เจ้าของเพิ่ม
4. หน้าอาหารค้นหา กรองวันหมดอายุ จัดลำดับ เลือกแก้ไขหรือนำออกหลายรายการ และกดดาวของโปรดได้ ทุกการเปลี่ยนอาหารส่งผ่าน API ของตู้นั้น
5. หน้าอุปกรณ์และกราฟแสดงเฉพาะข้อมูลที่ Gateway ส่งเข้าจริง ถ้าไม่มีข้อมูลจะแสดงสถานะว่าง กราฟเลือกเซนเซอร์และช่วงเวลาได้ สูงสุด 2,000 ตัวอย่างและเหตุการณ์ประตูล่าสุด 25 รายการ จึงไม่ใช่ยอดเหตุการณ์ทั้งหมดในช่วงเวลา

การเป็นสมาชิกตู้ทำให้เห็นข้อมูลและแก้ไขอาหารร่วมกันได้ รายการโปรดและการแจ้งเตือนส่วนบุคคลแยกตามบัญชี Google สมาชิกอื่นอ่านรายการโปรดของคุณผ่าน API ไม่ได้

## เชื่อม LINE ของครอบครัว

เจ้าของเปิด Settings → LINE ของครอบครัว เพิ่มเพื่อนบอทและเชิญบอทเข้ากลุ่ม สร้างรหัสจากเว็บ แล้วส่งรหัสนั้นในกลุ่มที่ต้องการ หน้าเว็บจะตรวจสถานะให้เอง ไม่ต้องคัดลอก User ID หรือ Group ID

หนึ่งตู้เลือกแชทปลายทางได้หนึ่งแชท รองรับกลุ่มหรือแชทตรงกับบอท ข้อความกลุ่มใช้การแจ้งเตือนและสรุปของตู้ร่วมกัน ไม่มีรายการโปรดส่วนตัวของสมาชิก เจ้าของกดส่งข้อความทดสอบหรือตัดการเชื่อมต่อได้ การบันทึกชื่อตู้ไม่เปลี่ยนปลายทาง LINE ที่จับคู่ไว้

## เชื่อม LINE ส่วนตัว

แต่ละคนเปิดหน้าของฉัน → LINE ส่วนตัว เพิ่มเพื่อนและส่งรหัสในแชทตรงกับบอทเท่านั้น ห้ามส่งรหัสส่วนตัวในกลุ่ม รหัสมีอายุ 10 นาที ใช้ได้ครั้งเดียว สร้างใหม่แล้วรหัสเก่าของขอบเขตเดียวกันใช้ไม่ได้ บัญชีหนึ่งสร้างได้สูงสุดห้ารหัสในสิบนาที การออกจากระบบหรือถูกถอดสิทธิ์เจ้าของก่อนใช้รหัสตู้ทำให้จับคู่ไม่สำเร็จ

LINE ส่วนตัวหนึ่งบัญชีผูกกับบัญชี Google ได้หนึ่งบัญชี หากต้องการเปลี่ยนบัญชี ให้ตัดการเชื่อมต่อจากบัญชีเดิมก่อน QR code ใช้เพิ่มเพื่อนบอท ส่วนรหัสจับคู่แสดงแยกต่างหาก

ในหน้าของฉันเลือกเวลาและเปิดหรือปิดสรุปตอนเช้า การเตือนประตู อุณหภูมิ และ VOC ได้ เวลาใช้ Asia/Bangkok สรุปรวมเฉพาะตู้ที่ยังเป็นสมาชิก พร้อมอาหารใกล้หมดอายุ ของโปรดที่เหลือหรือหมด และจำนวนเหตุการณ์ปิดประตูสำเร็จใน 24 ชั่วโมง ข้อมูล VOC เป็นสัญญาณให้ตรวจอาหาร ไม่ใช่ผลยืนยันความปลอดภัยของอาหาร

ระบบตรวจเวลาทุกนาที มีช่วงส่งชดเชยหนึ่งชั่วโมง และส่งสรุปได้หนึ่งครั้งต่อวันต่อบัญชี ถ้าไม่มีเรื่องรายงานจะไม่ส่ง ไม่รับประกันว่าส่งตรงวินาทีหรือถึงผู้ที่บล็อกบอท การเลือกเวลาใหม่หลังส่งสรุปวันนั้นไม่ทำให้ส่งซ้ำทันที

## การเปิดใช้ LINE สำหรับผู้ดูแลระบบ

ตั้งค่าของ Messaging API channel เดียวกัน:

- `LINE_CHANNEL_ACCESS_TOKEN`: secret สำหรับเรียก Reply/Push API
- `LINE_CHANNEL_SECRET`: secret สำหรับตรวจลายเซ็น webhook
- `LINE_BOT_BASIC_ID`: Basic ID สาธารณะที่ขึ้นต้นด้วย `@` เพื่อสร้างลิงก์และ QR เพิ่มเพื่อน เช่น `@foodwarden` ไม่ใช่ channel ID

ในเครื่องใช้ไฟล์ `.dev.vars` ที่ไม่ติด Git บน Cloudflare ใช้ Worker secrets สำหรับ token และ channel secret อย่าส่ง secret ผ่านแชทหรือเก็บในไฟล์ที่ commit

เมื่อ deploy แล้ว ให้ตั้ง Webhook URL เป็น `https://foodwarden.newisnooby.workers.dev/api/line/webhook` และเปิด Use webhook ใน LINE Developers เปิด Allow bot to join group chats หากจะใช้กลุ่มครอบครัว หากเปลี่ยนโดเมนต้องเปลี่ยน URL นี้ตามด้วย การกด Verify ส่ง payload ที่ไม่มี events ได้โดยต้องมีลายเซ็นถูกต้อง

Webhook ตรวจ HMAC-SHA256 บน request body เดิมก่อนอ่าน JSON มีขนาดสูงสุด 1 MB รหัสจับคู่ใน D1 เก็บเฉพาะ SHA-256 การใช้รหัสตรวจ session และสิทธิ์เจ้าของซ้ำในธุรกรรมเดียวกัน รองรับ webhook ซ้ำและลำดับ unfollow/leave ที่มาถึงช้ากว่าการเชื่อมใหม่

อ้างอิง: [ตรวจลายเซ็น LINE](https://developers.line.biz/en/docs/messaging-api/verify-webhook-signature/), [LINE URL scheme](https://developers.line.biz/en/docs/messaging-api/using-line-url-scheme/), [การ retry](https://developers.line.biz/en/docs/messaging-api/retrying-api-request/)

## ข้อความค้างและสิทธิ์ส่วนตัว

ข้อความส่วนตัวมี durable outbox แยกจากของตู้ ใช้ retry key เดิมเมื่อส่งซ้ำและตรวจปลายทาง การตั้งค่า และสมาชิกทุกตู้ที่รวมในข้อความก่อนส่ง การตัดการเชื่อมต่อ ปิดการแจ้งเตือน หรือจับคู่ใหม่ยกเลิกงานเก่าที่ค้างอยู่ งานผิดพลาดถาวรหรืออายุครบ 23 ชั่วโมงจะคงไว้พร้อม `failed = 1` เพื่อให้ตรวจสอบ ไม่ถือว่าส่งสำเร็จ

เช่นเดียวกับ API ที่อาศัยสิทธิ์ การเปลี่ยนสิทธิ์ขณะที่คำขอส่งไปยัง LINE แล้วไม่สามารถเรียกคืนข้อความที่ LINE รับไว้ได้ ปุ่มส่งทดสอบจำกัดหนึ่งครั้งต่อนาที และการแจ้งเหตุซ้ำใช้ event deduplication กับ cooldown

## ติดตั้งอุปกรณ์

การเปลี่ยนนี้ทำเฉพาะ `server/` ไม่ได้สร้างหรือ flash firmware:

- [Gateway C](../camera/README.md): ตั้งค่า URL Worker และโทเคนของตู้ใน `.env` พร้อม BLE AES key และ MQTT TLS ตามเอกสารของ Gateway
- [เซนเซอร์ F](../fridge/README.md): ตั้งค่า node ID และ AES key ให้ตรงกับ Gateway ใน `secrets.h` ตามแม่แบบ ส่งข้อมูลผ่าน BLE ไม่จำเป็นต้องต่อ Wi-Fi
- [ประตู D](../door/README.md): ตั้งค่า Wi-Fi, MQTT broker ของ Gateway, credentials และ CA certificate ตามแม่แบบ ห้ามข้าม fail-safe ของมอเตอร์

หน้าเว็บไม่สามารถพิสูจน์ว่าอุปกรณ์หรือ fail-safe ทำงานครบได้ ต้องทดสอบฮาร์ดแวร์จริงตาม [RUBRIC.md](../RUBRIC.md) แยกต่างหาก

## Migration และสถานะ rollout

เพิ่ม [0003_line_pairing_and_prefs.sql](migrations/0003_line_pairing_and_prefs.sql) ต่อจาก [0002_security_and_delivery.sql](migrations/0002_security_and_delivery.sql) ต้อง apply ทั้งสองก่อน deploy โค้ดชุดนี้ ฐานข้อมูลใหม่ต้องเริ่มจาก migration 0001 ตามลำดับ

รอบนี้ยังไม่ได้ apply migration บน production, deploy Worker หรือส่ง LINE จริง ดูขั้นตอนใน [PRODUCTION.md](PRODUCTION.md) การทดสอบ Worker ใช้ D1 จำลองและ mock LINE API ส่วน UI ใช้ DOM tests จึงยังต้องตรวจ Google sign-in, webhook จริง และการแสดงผลในเบราว์เซอร์ก่อนประกาศใช้งานจริง

```bash
bun install --frozen-lockfile
bunx wrangler d1 migrations apply foodwarden-db --local
bun run typecheck
bun run test:all
bun run lint
bun run knip
bun run format:check
bun run build
```

API ใหม่และสิทธิ์แต่ละ route แสดงใน [API reference](API-REFERENCE.md) และหน้า `/api/reference` หลังลงชื่อเข้าใช้
